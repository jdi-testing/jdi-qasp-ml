JDI-QASP-ml 0.3.1+

API for generating XPath locators and CSS selectors for elements on a web pages.

Servers

  • ws://localhost:5050/wsproduction

Operations

  • REPLY ws

    No authentication is required for communication.

    Operation IDscheduleXPathGeneration

    Available only on servers:

    • production

    Accepts the following message:

    Schedule XPath expression generationscheduleXPathGeneration

    Get XPath expressions for selected elements on the page

    Message IDscheduleXPathGeneration

    Request calculation of optimal XPath expressions for a set of the elements on the web page with some provided limitations (i.e. one can specify that some HTML attribute should not be used in resulting XPath expression because it contains dynamic data).

    Results are cached by elements' id in Celery. Advanced calculation may be requested to bypass cache.

    Calculation is performed using Robula algorithm.

    object
    action
    string
    Const:"schedule_multiple_xpath_generations"
    object
    document
    string

    HTML document to be used in calculations.

    Every element should have jdn-hash attribute, which value must be unique across the document and should be unique across documents.

    object

    Configuration and some limitations for Robula algorithm.

    maximum_generation_time
    integer

    Maximum amount of seconds which should be spent to find XPath expression for one element. No limits are applied if the value is null.

    Default value:null
    allow_indexes_at_the_beginning
    boolean

    Whether to allow resulting XPath expression to contain indexes at the beginning of expression (e.g. //div[1]/p).

    Default value:false
    allow_indexes_in_the_middle
    boolean

    Whether to allow resulting XPath expression to contain indexes in the middle of expression (e.g. //div[@class='flex']/div[2]/p).

    Default value:true
    allow_indexes_at_the_end
    boolean

    Whether to allow resulting XPath expression to contain indexes at the end of expression (e.g. //div/div/p[2]).

    Default value:true
    advanced_calculation
    boolean

    Ignore cached results and force recalculation.

    Default value:false
    array<string>

    Specify HTML attributes which must not be used in resulting XPath expression.

    This can come in handy when you know that some attributes' values are dynamically generated and thus can not be used to reliably locate an element on the page on subsequent page loads.

    Some attributes are ignored by default, user-defined list is added to that set. Attributes ignored by default:

    • href
    • src
    • onclick
    • onload
    • tabindex
    • width
    • height
    • style
    • size
    • maxlength
    • jdn-hash
    • xml:space
    • fill
    • xmlns
    • data-label
    Default value:null
    Items:
    string

    Additional properties are allowed.

    array<string>
      Examples values:
    • [111111,222222,333333]
    • [222222]
    Items:
    string

    Value of elements' jdn-hash attribute.

    Additional properties are allowed.

    object

    Information for application usage analytics.

    session_id
    integer

    Unique session id generated by client.

    element_library
    string

    Library chosen for page object generation.

      Allowed values:
    • "HTML5"
    • "MUI"
    • "Vuetify"
    page_object_creation
    string

    Page object name

    website_url
    string

    Full URL to the analyzed web page.

    Additional properties are allowed.

    Additional properties are allowed.

    Examples

    {
  "action": "schedule_multiple_xpath_generations",
  "payload": {
    "document": "<html lang=\"en\" jdn-hash=\"111111\"><body id=\"body\" jdn-hash=\"222222\"><h1 jdn-hash=\"333333\">Hello</h1></body></html>",
    "config": {
      "maximum_generation_time": 10,
      "allow_indexes_at_the_beginning": false,

    • #4Generated CSS selectorCSSSelectorGenerationResult

      Best found unique CSS selector for an element

      Message IDCSSSelectorGenerationResult

      Results are returned using an array although array contains only one element. It's done for compatibility with the old API where several elements could be returned in one result message.

      Resulting selector could be empty in case underlying libraries failed to find it.

      Results are cached by elements' id for one day (24 hours). Currently there is no other way to bypass the cache and force recalculation apart from changing element id.

      object
      action
      string
      Const:"result_ready"
      object
      id
      string
      array<object>
      object
      id
      string

      Value of elements' jdn-hash attribute.

      result
      string

      CSS selector for the element.

      Additional properties are allowed.

      Additional properties are allowed.

      Additional properties are allowed.

      Examples

      {
  "action": "result_ready",
  "payload": {
    "id": "css-selectors-gen-73de49b0-2b1b-4bf0-a3a1-23f546e8f765",
    "result": [
      {
        "id": "222222",
        "result": "div:nth-child(4) > .mt-2"
      }
    ]
  }
